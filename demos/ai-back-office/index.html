A finance back office you can try to break.

Payment documents arrive by email. This system reads them, matches them to open invoices and posts only exact matches to the accounting system. An AI agent investigates everything else and proposes what to do. A named person has to approve it.

        How it was attacked
        
    
        Separate Claude agents that hadn't built this were told to break it, and each break had to be shown with a script that runs. They found serious problems after every test above had passed.

        What these numbers don't show
        
    
          
      
        • A remittance is only a customer's claim. A real system also needs matching against the bank statement.
          • 
      
        • The test sets aren't independent. The same process wrote the documents, the labels, the attacks and the code.
          • 
      
        • The AI results are small: one run per test set, so they say little about how consistent Claude is across repeats.
          • 
      
        • A customer who knows the exact amount and simply writes "paid" still gets it posted. Only a bank statement can catch that.
          • 
      
        • The attackers are Claude too, working on the same made-up data. People with real documents would find other things.
          • 
      
        • The latest live runs went through Claude Code on a subscription, so their costs are estimates at API prices, and the agent's API code has only run against a fake.
          • 
      
        • The hours a system like this saves are assumed here, so they aren't on this page. Nothing has run on real paperwork.
